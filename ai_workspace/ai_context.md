# AI 协助开发入口

本文件是 AI 协作开发的本项目**统一入口**。开始任何开发或分析任务前，请先阅读本文并遵守工作区约定。

---

## 三、新功能开发流程（必遵）

**原则**：先出「改动方案」，评审通过后再动手改代码。

### 3.1 第一步：输出改动方案

在实现代码前，AI 必须先输出并等待确认：

- **影响范围**：哪些模块、端（用户端/管理端）、依赖服务
- **涉及文件**：预计新增/修改的文件列表
- **接口变化**：新增/修改的 API 路径、方法、请求/响应结构
- **表结构变化**：新增/修改的表、字段、索引（含建表/变更 SQL 草稿）
- **风险点**：兼容性、数据迁移、性能、权限等
- **实施顺序**：建议的步骤（如：表结构 → 后端 API → 管理端 → 用户端）

### 3.2 第二步：确认后再实现

- 用户确认方案合理后，再按 **实施顺序** 开始改代码。
- 实现时：**不要修改已有方法的参数**，避免影响现有功能；如需扩展，优先新增方法或新接口。
