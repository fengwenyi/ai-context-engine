# 新项目套用指南

> 把这套 `ai_workspace/` 方法搬到一个新项目，3 步走。

---

## 步骤

### 1. 拷贝 `ai_workspace/` 整个目录到新项目根

```
新项目/
├── ai_workspace/        ← 拷贝过来
└── ...（你的代码）
```

### 2. 清理新项目专属内容

清空（保留目录本身）：
- `project/designs/` 下的所有文件
- `project/apis/` 下的所有文件
- `project/ai_files/` 下的所有文件
- `features/` 下除示例外的所有目录（可保留 `feature_xxx/` 作为模板示例）

保留不动（这是通用方法论本体）：
- `AI_CONTEXT.md`
- `method/` 整个目录

### 3. 填写 `project/项目介绍.md`

按模板填写：
- 项目名与定位
- 端清单（后端 / 管理端 / 用户 Web / 小程序 / App，分别在哪个目录）
- 各端技术栈
- 关键代码结构
- 项目特定的约定（表前缀、命名、特殊规范）

---

## 启用

完成后，下一次让 AI 协作时，发送：

```
开始任务前，请按下列顺序执行：
1. 阅读 @ai_workspace/AI_CONTEXT.md
2. 阅读 @ai_workspace/project/项目介绍.md
3. 判断本任务属于场景 1 / 2 / 3，按对应 workflow 执行
4. 在动手前先输出"改动方案"，等我确认

需求：{你的需求}
```

AI 会自动加载入口与项目介绍，进入正确的 workflow。

## 三类场景速查

| 场景 | 什么时候用 |
|---|---|
| [场景 1：项目设计](../workflows/01-项目设计.md) | 全新项目，从 0 设计 |
| [场景 2：新系统开发](../workflows/02-新系统开发.md) | 项目已有，但模块从 0 |
| [场景 3：功能迭代](../workflows/03-功能迭代.md) | 增量改动、bug 修复 |

---

## 维护建议

- 每个项目可以根据自身需要**扩充** `project/`，但**尽量不要改** `method/`
- 如果 `method/` 中某规范/模板长期不适用，反过来更新 `method/`，让方法论本体进化
- 多个项目积累的经验，可定期回流到 `method/`
