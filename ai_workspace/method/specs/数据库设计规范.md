# 数据库设计规范

> 通用关系型数据库设计原则。具体数据库的方言由项目自定。

---

## 1. 命名
- 表名：小写下划线、单数或复数项目内统一（建议复数：`users`、`orders`）
- 字段名：小写下划线：`created_at`、`user_id`
- 索引名：`idx_{表}_{字段}`，唯一索引 `uk_{表}_{字段}`，外键 `fk_{表}_{字段}`
- 主键：默认 `id`
- 项目级表前缀建议在 `project/项目介绍.md` 中声明

## 2. 必备字段
每张业务表至少包含：
- `id`：主键
- `created_at`：创建时间
- `updated_at`：更新时间
- 软删除字段（如启用）：`deleted_at` 或 `is_deleted`

## 3. 字段类型
- 主键：`bigint unsigned`，自增或雪花 ID
- 金额：`decimal(N,M)`，禁用 `float` / `double`
- 时间：`datetime` 或 `timestamp`（项目内统一）
- 布尔：`tinyint(1)` 或数据库原生 bool
- 字符串：合理估算长度，避免一律 `varchar(255)`
- JSON：原生 JSON 类型；非结构化才用 `text`
- 枚举：用 `tinyint` + 代码层映射，禁用 `enum` 类型

## 4. 索引
- 主键聚簇索引由数据库管理
- 查询频繁的字段建索引；最左前缀原则
- 避免冗余索引（前缀已被其它索引覆盖）
- 唯一性约束建唯一索引
- 索引字段不超过 5 个

## 5. 关系
- 外键关系**在文档中明确标注**
- 是否启用数据库外键约束由项目决定（互联网项目常不开）

## 6. 设计原则
- 适度反范式以换查询性能，要在设计文档中说明
- 大字段（长文本、二进制）独立成表
- 历史/归档数据走独立表

## 7. 变更（DDL）
- 所有 DDL 必须有对应 SQL 文件入版本控制（`features/{x}/outputs/sql/`）
- 大表变更评估锁表/在线 DDL 工具
- 变更前考虑回滚 SQL

## 8. 数据安全
- 敏感字段加密存储（手机号、身份证、密钥）
- 密码必须哈希（bcrypt / argon2），禁止明文/可逆
- 备份策略由项目定义

## 9. 性能
- 避免 `SELECT *`，按需取列
- 大数据量分页避免深翻页，必要时游标分页
- 慢查询阈值在项目内定义并监控
