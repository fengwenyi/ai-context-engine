# 接口设计规范

> 通用接口设计原则，技术栈无关。具体框架的实现细节由项目自定。

---

## 1. 路径与命名
- 使用小写 + 短横线分词：`/api/v1/user-orders`
- 使用名词复数表示资源集合：`/api/v1/users`
- 嵌套不超过 2 层：`/api/v1/users/{id}/orders`
- 动词类操作可用子路径：`/api/v1/orders/{id}/cancel`

## 2. 版本
- 路径前缀带版本号：`/api/v1/...`
- 不兼容变更升版本：`v1 → v2`

## 3. HTTP 方法语义
| 方法 | 语义 |
|---|---|
| GET | 查询，幂等，无副作用 |
| POST | 创建 / 动作触发 |
| PUT | 全量替换，幂等 |
| PATCH | 局部更新 |
| DELETE | 删除，幂等 |

## 4. 请求
- 列表查询的过滤、分页、排序统一用 query：`?page=1&page_size=20&sort=-created_at&status=active`
- 复杂查询体走 POST + body
- 时间统一 ISO 8601
- ID 在路径中：`/users/{id}`

## 5. 响应
统一结构：
```json
{ "code": 0, "message": "ok", "data": {} }
```
- `code = 0` 成功，其它为业务错误码
- HTTP 状态码用于传输层（200 / 401 / 403 / 404 / 5xx）；业务错误用 `code`

## 6. 错误码
- 项目级统一错误码表（建议 4 位整数：4xxx 客户端 / 5xxx 服务端）
- 每个错误码有明确含义与对应场景

## 7. 鉴权
- Token 放 `Authorization: Bearer xxx` 或自定义 Header（项目内统一）
- 无需鉴权的接口显式标注

## 8. 分页
- `page` 从 1 开始；或用 `cursor`
- 列表返回包含 `total`、`page`、`page_size`、`list`

## 9. 幂等
- POST 创建类支持幂等键：`Idempotency-Key` Header

## 10. 安全
- 输入做白名单校验
- 敏感字段（密码、密钥、手机、身份证）不出现在日志、URL、响应中
- 文件上传限制类型与大小
- 防 SQL 注入、XSS（参数化查询、转义输出）

## 11. 文档同步
- 接口实现完成后**必须**同步更新接口文档（`project/apis/`）
- 文档与代码不一致视为 bug
