# UI 设计规范

> 通用 UI 设计与"UI 提示词"撰写原则，框架无关。

---

## 一、视觉一致性

- 项目级统一色板（主色、辅助色、状态色）
- 字体系统：标题、正文、辅助文本三档字号
- 间距系统：4 / 8 的倍数
- 圆角：统一一两种值
- 阴影：分层 1-3 级
- 图标：风格统一（线性 / 面性 / 双色，二选一）

## 二、布局原则

- 信息层级清晰：标题 > 主要内容 > 次要内容 > 操作
- 操作按钮位置一致：主操作右下/右上，破坏性操作位置固定
- 留白足够，不要塞满
- 一屏只解决一件主要事

## 三、组件复用

- 列表页、详情页、表单页有项目级统一模板
- 表格、分页、筛选、表单字段统一组件
- 弹窗、抽屉、消息提示统一交互

## 四、交互规范

- 操作有反馈：loading、success、error
- 危险操作二次确认（删除、批量、不可逆）
- 表单实时校验、错误即时提示
- 长流程显示进度

## 五、状态展示

每个数据展示页面必须考虑：
- 加载中（骨架屏 / loading）
- 空状态（友好提示 + 引导动作）
- 错误（错误信息 + 重试）
- 异常权限（无权限 / 未登录）

## 六、响应式（Web）

- 至少 3 档断点：移动 / 平板 / 桌面
- 关键操作在所有断点可用

## 七、可访问性

- 文本与背景对比度足够
- 操作元素点击区域 >= 44×44px（移动）
- 表单 label 与控件正确关联

## 八、UI 提示词撰写要点

写提示词给 UI AI 工具时，至少覆盖：

1. **页面目标**：用户来这做什么
2. **端与形态**：Web / 移动；列表 / 详情 / 表单
3. **布局**：分区、栅格
4. **组件**：每个区域有哪些组件、关键属性
5. **交互**：点击/选中/批量等行为
6. **状态**：空/错误/加载
7. **风格基调**：色调、密度、圆角
