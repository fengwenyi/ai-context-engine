# 文档规范

> 何时写、写到哪、谁更新。

---

## 1. 文档分级

| 级别 | 范围 | 位置 |
|---|---|---|
| 项目级 | 产品、架构、技术选型、数据库总览 | `project/designs/` |
| 接口级 | 调用方使用的接口文档 | `project/apis/` |
| 功能级 | 单个功能的需求、设计、迭代 | `features/{x}/{x}.md` |
| 交付物 | 功能产生的 SQL、UI 提示词、联调记录 | `features/{x}/outputs/` |
| AI 自治 | AI 沉淀的理解、QA、决策 | `project/ai_files/` |

## 2. 何时写
- **设计前**：项目级文档、模块设计（写在功能文档内）
- **实现前**：改动方案
- **实现中**：必要的代码注释（仅 WHY）
- **实现后**：接口文档、CHANGELOG、必要的 ai_files 笔记

## 3. 谁写
- 一律 AI 主笔，用户审阅与确认
- 用户的口头决策必须由 AI 同步进文档

## 4. 格式
- 一律 Markdown
- 全中文（项目内统一）
- 标题层级清晰：H1 文件标题、H2 主章节、H3 小节
- 表格代替罗列长字段
- 代码块标语言：```` ```sql ```` `` ` ```bash ```` ``

## 5. 命名
- 功能目录与文档：`{编号}-{名称}`
- 接口文档：`{模块名}.md`
- SQL：`{功能编号}-{简述}.sql`
- UI 提示词：`{页面名}.md`
- ai_files 笔记：`{功能编号}-{话题}.md` 或 `topic-{主题}.md`

## 6. 内容原则
- **写决策与依据**，不写显而易见的事
- **写 Why**，不写 What（What 看代码）
- **写本次新增/变更**，引用而非复制其它文档内容
- **不写过时即失效的内容**（如"当前进行中"，要么状态字段化要么直接删）

## 7. 更新责任
- 接口实现完成 → 同步接口文档
- 表结构变更 → 同步数据库设计文档
- 功能迭代完成 → 同步功能文档"任务状态" + CHANGELOG
- 项目特性变化 → 同步 `project/项目介绍.md`
