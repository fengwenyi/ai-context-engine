# 场景 2：新系统 / 新模块开发

> 触发：项目已存在，但该业务模块/系统从 0 开始，需走"设计→开发→联调"完整闭环。
> 目标：从需求到上线，所有产物可追溯。

---

## 流程总览

```
需求
  ├─ 0. 建功能目录 + 改动方案
  ├─ 1. 模块设计（业务/数据/接口）
  ├─ 2. 数据库设计 → SQL
  ├─ 3. 接口设计
  ├─ 4. 后端接口开发
  ├─ 5. 输出接口文档
  ├─ 6. UI 提示词（用于 UI AI 工具生成 UI）
  ├─ 7. 前端页面开发
  ├─ 8. 接口联调
  ├─ 9. 管理端动态路由配置（如适用）
  └─10. 沉淀（CHANGELOG / ai_files）
```

---

## 步骤详解

### 0. 建功能目录 + 改动方案
- 在 `features/` 下建 `{编号}-{名称}/`，用 [功能迭代模板](../templates/功能迭代模板.md) 初始化主文档
- 按 [改动方案模板](../templates/改动方案模板.md) 输出方案，等用户确认
- ⚠ 没确认前不进入下一步

### 1. 模块设计
- **产物**：`features/{x}/{x}.md` 的"需求梳理"区 + `project/designs/` 下补充（如属基础能力）
- **模板**：[系统设计模板](../templates/系统设计模板.md)

### 2. 数据库设计
- **产物**：
  - 设计说明：写在功能主文档内或 `project/designs/`
  - 建表 SQL：`features/{x}/outputs/sql/{x}.sql`
- **模板**：[数据库设计模板](../templates/数据库设计模板.md)
- **规范**：[数据库设计规范](../specs/数据库设计规范.md)

### 3. 接口设计
- **产物**：`features/{x}/{x}.md` 的接口设计区，或 `project/apis/{x}-design.md`
- **模板**：[接口设计模板](../templates/接口设计模板.md)
- **规范**：[接口设计规范](../specs/接口设计规范.md)

### 4. 后端接口开发
- 按接口设计实现
- **规范**：[代码与提交规范](../specs/代码与提交规范.md) + `project/项目介绍.md` 里项目特定的代码约定

### 5. 输出接口文档
- **产物**：`project/apis/{模块名}.md`
- **模板**：[接口文档模板](../templates/接口文档模板.md)
- 接口文档以"调用方视角"写，覆盖路径、请求、响应、错误码、示例

### 6. UI 提示词
- 目的：用文字描述给专业 UI AI 工具，让其生成 UI 稿
- **产物**：`features/{x}/outputs/ui-prompts/{页面名}.md`
- **模板**：[UI 提示词模板](../templates/UI提示词模板.md)
- **规范**：[UI 设计规范](../specs/UI设计规范.md)

### 7. 前端页面开发
- 基于生成的 UI 图实现页面
- 必要时反向调整 UI 提示词，沉淀经验

### 8. 接口联调
- **产物**：`features/{x}/outputs/联调清单.md`
- **模板**：[联调清单模板](../templates/联调清单模板.md)
- 每个接口逐条验证：请求/响应/边界/异常

### 9. 管理端动态路由配置（如适用）
- **产物**：`features/{x}/outputs/routes.json`（或对应格式）
- 包含菜单、权限、路由声明

### 10. 沉淀
- 更新功能主文档的"任务状态"
- 写 `features/{x}/CHANGELOG.md`
- 必要时把决策/踩坑写入 `project/ai_files/`

## 交付物 Checklist

完成时确认下列文件齐全（按需，无则注明"无"）：

- [ ] 功能主文档（`features/{x}/{x}.md`）
- [ ] 数据库 SQL（`outputs/sql/`）
- [ ] 接口文档（`project/apis/`）
- [ ] UI 提示词（`outputs/ui-prompts/`）
- [ ] 联调清单（`outputs/联调清单.md`）
- [ ] 管理端路由配置（`outputs/routes.json`）
- [ ] CHANGELOG 已追加
- [ ] ai_files 笔记（如有沉淀）
